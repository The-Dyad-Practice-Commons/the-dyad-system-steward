## Falsification
Record: `agent-corpus/falsification/5-plan-gate-ledgerless.md` (written with the PR; the upstream
amendment is step 4's).

- **A1 — the skip hides a real citation fault.** Attack: a dyad system whose branch cites a bogus row
  now passes. *Refuted*: the skip fires only when the base holds no row store at all. A dyad system's
  `origin/main` holds rows from its first d-work on, and the row guard's append-only fence refuses any
  commit that deletes one, so the store cannot be emptied to buy the skip. The rewritten test asserts
  exactly that boundary.
- **A2 — a fresh dyad system loses the gate on its first branch.** *Survives, scoped*: it does, and
  there is nothing to lose — before its first row no citation can resolve, and the commit that writes
  that first row is ledger-only, which the gate already skips. From the second push on, the gate is
  whole.
- **A3 — the reference should carry a ledger instead.** Attack: seed `agent-corpus/d-work/` in the
  reference and the gate works unchanged. *Confirmed as an alternative, rejected on the operator's own
  words*: the reference's own commit says "No instance: ledger, preferences values, host records and
  site stay in the source system". A ledger in the distribution would also mean contributors citing rows
  of a ledger they cannot write, and a steward merging rows from strangers. The same argument rejects
  seeding `preferences-corpus/` for step 3.
- **A4 — the test change is the defect, not the guard.** Attack: #715 *decided* this behaviour, and a
  test asserts it; changing it is reversing a decision, not fixing a fault. *Confirmed, and stated*:
  #715 asked that a ledger-less base not crash the gate, and got that. It did not ask whether a
  repository that will never hold a ledger should be gated at all — the reference did not exist then.
  This row answers that question for the first time, which is why it amends the Rule's text and its
  record rather than calling itself a restoration. It is therefore **not** a candidate for the
  intake-mandate of #7, whose class is defects that only restore stated behaviour.
- **A5 — D3 does not belong in a row titled D1.** *Survives, scoped*: the row's title names D1 and its
  definition of done names the contributor's push, which D3 refuses on its own. Carrying it here costs
  one plan question instead of two and keeps one PR where two would have to be ordered anyway. If the
  operator would rather judge it separately, this plan is refused with `N` and the frame fix returns as
  its own row.
- **A6 — 1.6.1 is the wrong number.** *Survives, scoped*: a defect fix that adds no public surface
  reads as a patch. The counter is that a gate which now declines to judge is a behaviour change a
  downstream system can observe, which argues 1.7.0. The number binds the later release row, not this
  one; it is called out in the reply so the operator can set it with the plan-`Y`.
- **A7 — concurrency.** No other session's presence file claims any file this plan touches
  (`program` holds no rows; `maintain` holds #3, whose files are `workstation-corpus/ops/` and the
  change log — the change log is shared with step 7 and is appended, one row, at the end).
